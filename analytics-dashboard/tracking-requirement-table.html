📍 新增 — 页面行为（用户停留 & 流失分析）
页面行为 自动 hq_page_leave 用户离开当前页面时上报（站内跳转 / 关闭页面）
—
无 UI 交互
 page_id: 当前页面标识
duration_ms: 在本页可见状态的毫秒数
leave_type: navigate(站内跳转) / close(关闭或返回)
next_page_id: 站内跳转目标（leave_type=close 时为空）		 核心：知道用户每页停了多久、为什么离开、去了哪里 1.1 触发时机：① 站内链接点击时，在跳转前上报 leave_type=navigate（从 href 取 next_page_id）；② beforeunload 时上报 leave_type=close。
duration_ms 计算：页面 pageshow 时记录 T1，visibilitychange=hidden 时暂停计时、=visible 时恢复，最终上报累计可见时长。
注意：visibilitychange 仅用于暂停计时，不触发 leave 上报（切标签页不算离开）。用 sendBeacon 确保 beforeunload 时能发出。
页面行为 自动 hq_scroll_depth 页面滚动达到 25% / 50% / 75% / 100% 阈值时
—
无 UI 交互
 page_id: 当前页面
depth: 25 / 50 / 75 / 100（整数）		 核心：用户看到了多少内容，定位内容断层位置 1.1 计算：scrollTop / (scrollHeight - clientHeight) * 100。每个阈值每页仅触发1次（用 Set 记录）。加 500ms debounce。
边界处理：若 scrollHeight ≤ clientHeight（页面无需滚动），则页面加载完成后直接上报 depth=100。
监听对象：window scroll 事件（非内部容器滚动）。
📍 新增 — 异常监控
异常 自动 hq_error 页面 JS 报错或资源加载失败
—
无 UI 交互
 error_type: js_error / load_error
error_msg: 错误信息（前200字符）
page_id: 当前页面		 技术异常导致的流失排查 1.1 js_error: window.addEventListener('error') + window.addEventListener('unhandledrejection') 全局监听。
load_error: window.addEventListener('error', cb, true) 捕获阶段监听资源加载失败（img/script/css）。
防刷：同一 error_msg 每页面最多上报 3 次。
