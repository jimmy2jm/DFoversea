## User Requirements

- 在桌面网页原型中增加“爆破模式”，与“烽火地带”“全面战场”并列。
- 本期只规划并实现首页爆破日报、个人爆破战绩及单局详情，不同步改造移动端。
- 本期仅使用中文界面，不投入中德多语言资源维护。
- 个人战绩顶部汇总区先完成结构与占位状态，暂不要求真实汇总数值。
- 用户确认方案后再开发；实施时保留现有未提交代码，不覆盖或还原已有修改。

## Product Overview

爆破功能形成“首页日报摘要 → 个人战绩列表 → 单局详情”的完整浏览链路。首页用于快速查看昨日表现，个人页承载长期战绩，详情页展示双方计分板、个人表现和回合过程。

整体视觉延续现有深色军事工具站风格，使用紧凑直角面板、绿色数据高亮和清晰的胜负状态，不直接放大小程序布局。

## Core Features

### 首页爆破日报

- 新增爆破日报第三个模式页签。
- 展示日期、对局场数、胜负、胜率、MVP、K/D/A、爆头率、下包和拆包等摘要。
- 展示当日代表对局，可直接进入对应单局详情。
- 提供“查看完整战绩”入口，跳转至爆破个人战绩。
- 爆破状态下隐藏烽火、战场专属改枪推荐；暂不提供爆破分享海报，避免错误复用战场内容。

### 个人爆破战绩

- 新增爆破一级模式，通过 `my-data.html?mode=baopo` 直接访问。
- 顶部汇总区预留段位、场次、胜率、KDA、ACS、ADR、攻守胜率等指标，当前统一显示数据接入占位。
- 战绩列表展示胜负、地图、比分、时间、干员、K/D/A、评分及下包拆包贡献。
- 支持地图、结果筛选和分批加载，并保留筛选 URL 状态。
- 提供无战绩、无筛选结果和数据不可用状态。

### 单局详情

- 使用稳定 `matchId` 的独立详情页面。
- 展示比赛概览、双方阵容计分板、玩家展开数据、攻守信息及逐回合时间线。
- 回合结果区分淘汰、引爆、拆除、超时等原因。
- 无有效 `matchId` 时显示错误状态和返回战绩入口。

## Tech Stack Selection

- **页面架构**：沿用原生 HTML 多页面结构，不引入前端框架或路由器。
- **交互逻辑**：原生 JavaScript，使用现有 DOM 事件与 URL 参数模式。
- **样式系统**：复用 `desktop/main.css` 和 `design.md` 规定的设计变量与正式版覆盖分区。
- **数据来源**：本期使用结构化共享 Mock 数据，后续可直接替换为接口返回。
- **界面文案**：本期直接维护中文文案，不调整 `desktop/locales/` 下的中德文资源文件。

## Implementation Approach

建立单一爆破 Mock 数据源，同时驱动首页日报、个人列表和单局详情，日报指标由对局明细计算，避免三个页面各自维护矛盾常量。首页与个人页只扩展现有模式切换，单局详情采用独立 URL，保证可返回、可刷新和可分享。

### 关键技术决策

1. **模式标识统一**

- 新模式使用规范值 `baopo`。
- 保留首页旧值 `fenguo`，通过显式模式配置映射兼容，暂不全站重命名旧枚举。
- 首页日报和个人页模式切换从二元分支改为模式到内容容器的映射，避免第三模式误入战场逻辑。

2. **共享数据而非复制 HTML 常量**

- `shared/demolition-mock.js` 暴露只读数据与安全查询方法。
- 首页日报从指定日期的比赛中聚合场数、胜负和目标贡献。
- 列表和详情使用相同 `matchId` 查找比赛，确保比分、回合数、K/D/A、下包拆包相互一致。
- 数据保留 `rulesetVersion`，不在 UI 中写死率先获胜分数、换边和加时规则。

3. **个人汇总明确占位**

- 汇总区只定义稳定指标槽位和“数据接入中”状态，不用虚构百分比填满页面。
- Mock 明细仅服务日报、列表和详情演示；未来接入赛季聚合接口时无需调整布局。

4. **独立详情页**

- 路径建议为 `desktop/demolition-match.html?matchId=...`。
- 不复用现有烽火、战场静态 Modal，避免继续扩大 `my-data.html` 内部弹窗逻辑。
- 战绩项使用独立类名与普通链接，避免被现有 `.match-record-item` 全局事件委托拦截。

## Architecture Design

### 数据流

- `shared/demolition-mock.js`
- 提供规则版本、比赛、参与者、回合和目标事件。
- 提供按日期聚合日报、按条件筛选比赛、按 `matchId` 查询详情的方法。
- `desktop/main.js`
- 管理首页三模式切换、爆破日报渲染、关联模块显隐和分享按钮状态。
- `desktop/demolition-records.js`
- 管理个人爆破模式初始化、筛选、分页、URL 状态和列表渲染。
- `desktop/demolition-match.js`
- 校验 `matchId`，渲染比赛概览、计分板、玩家展开数据和回合时间线。

### 核心数据边界

- **Ruleset**：`rulesetVersion`、队伍人数、换边与胜负配置。
- **Match**：稳定 ID、地图、队列、开始时间、比分、胜方、排位变化。
- **Participant**：队伍、干员、评分、K/D/A、伤害、命中、首杀、目标贡献。
- **Round**：回合序号、攻守方、胜方、结束原因、包点、下包与拆包事件。
- **DailySummary**：由 Match、Participant、Round 聚合，不单独复制业务明细。

## Performance and Reliability

- 首页日报聚合复杂度为 `O(M + P + R)`，其中 M 为当日对局数、P 为参与者数、R 为回合数；仅在初始化或日期变化时计算一次。
- 战绩筛选为 `O(M)`，使用 `DocumentFragment` 批量渲染，默认分批展示，避免重复创建全部节点。
- 详情页只查询当前 `matchId`，不渲染无关比赛。
- 使用事件委托处理列表和计分板交互，避免为每行重复注册监听器。
- Mock 数据加入基本一致性校验：比分等于胜负回合统计、玩家目标次数不超过有效回合、日报胜率可由场次还原。
- 动态数据使用 `textContent` 或转义后输出，为后续 API 数据接入保留安全边界。

## Implementation Notes

- 修改 `desktop/index.html`、`desktop/main.js`、`desktop/main.css` 时只做增量编辑，保留当前未提交内容。
- 爆破日报激活时禁用现有分享海报入口并给出明确状态；切回旧模式后恢复。
- 爆破态隐藏 `gun-builds-fenguo` 和 `gun-builds-zhanchang`，不展示错误模式推荐。
- 列表筛选和分页通过 `history.replaceState` 保存，不触发整页刷新。
- 不显示没有真实能力的视频播放、排行榜、AI 点评或流派码按钮。
- 不引入 Chart.js 或其他新依赖，避免增加首屏网络和资源开销。
- 实施后进行 HTML、JavaScript 静态检查和 Mock 数据一致性检查；遵循工作区规则，不使用 DevChrome 验证，由用户进行视觉验收。

## Verification Criteria

- 三个首页日报 Tab 可独立切换，爆破态不会显示战场日报或旧改枪推荐。
- 爆破日报数据可由共享对局数据计算，并与对应详情一致。
- `my-data.html?mode=baopo` 可直接打开爆破战绩，旧模式 URL 保持可用。
- 筛选、加载更多、无结果状态和刷新后的 URL 状态工作正确。
- 每条战绩进入唯一 `matchId` 详情，刷新后仍能恢复同一场比赛。
- 双方计分板人数、比分、回合胜负、下包拆包次数不存在逻辑冲突。
- 非法或缺失 `matchId` 不报错，显示可返回的错误状态。
- 页面符合 `design.md`，除头像外无圆角，不影响现有烽火和战场页面。

## Design Direction

采用高信息密度的战术数据终端风格。爆破模式沿用现有深青背景、直角面板、细边框和品牌绿高亮，通过胜负色、攻守标签、比分和回合轨迹建立区别，不引入独立的彩色主题或装饰性插画。

## Screen 1：首页爆破日报

1. **顶部导航与日报模式栏**：保留现有主导航，日报栏扩展为三等分，爆破激活态使用品牌绿底和深色文字。
2. **昨日作战摘要**：以比分式布局展示场数、胜负、胜率、MVP 和 K/D/A，数字使用等宽数据字体。
3. **爆破专项数据**：紧凑排列爆头率、首杀、下包、拆包及攻守回合表现，辅助文字解释样本范围。
4. **代表对局与入口**：突出当日最佳对局、地图、比分和个人表现，提供单局详情及完整战绩入口。
5. **关联模块状态**：切换爆破后隐藏旧模式改枪推荐，其他首页模块保持原位，避免布局跳动。
6. **底部信息区**：保留原页面更新时间和页脚结构，标明日报统计日期。

## Screen 2：个人爆破战绩

1. **顶部导航与一级模式栏**：在现有模式栏加入爆破，三个模式宽度一致，支持 URL 直接定位。
2. **玩家与赛季信息**：保留账号、赛季和更新时间，段位未接入时显示明确占位而非模拟等级。
3. **汇总占位面板**：按战斗、回合、目标三个分组预留指标，使用 `--` 和“数据接入中”状态。
4. **战绩筛选栏**：提供地图、胜负筛选和总结果数，控件紧凑排列并保持键盘可操作。
5. **战绩列表**：每行按结果、地图比分、干员、K/D/A、评分和目标贡献分区，整行可进入详情。
6. **分页与空状态**：使用“加载更多”增量展示；无数据时给出简洁说明和清除筛选操作。

## Screen 3：爆破单局详情

1. **导航与返回路径**：顶部沿用站点导航，下方提供返回爆破战绩的明确面包屑。
2. **比赛概览**：集中展示胜负、地图、比分、时间、队列、时长与段位变化。
3. **双方计分板**：桌面端上下排列两队，列出干员、评分、K/D/A、ACS 和目标贡献。
4. **玩家展开详情**：点击行展开伤害、命中分布、首杀首死、多杀、下包拆包和经济信息。
5. **回合时间线**：按回合展示攻守、获胜方、包点及淘汰、引爆、拆除、超时原因。
6. **数据说明与页脚**：展示规则版本、更新时间及 Mock 数据标识，避免被误解为线上真实数据。

## Agent Extensions

### SubAgent

- **code-explorer**
- **Purpose**：实施前复核首页、个人页和共享脚本的调用关系，重点识别现有未提交修改及二元模式判断。
- **Expected outcome**：确认精确增量编辑位置，避免爆破逻辑干扰烽火、战场切换和旧战绩 Modal。
