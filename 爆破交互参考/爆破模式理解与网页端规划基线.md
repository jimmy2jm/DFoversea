# 爆破模式理解与网页端规划基线

> 用途：作为后续网页端爆破功能规划、接口设计和指标对齐的共同基线。
>
> 输入原型：`爆破战绩参考.html`、`20260714170612/爆破日报.html`、`20260714170612/数据详情.html`。
>
> 当前结论来自原型和公开测试信息。由于黑潮爆破仍处于测试迭代阶段，规则相关字段必须支持 `rulesetVersion`，未确认口径不能写死。

## 1. 模式定位

黑潮爆破应作为与“烽火地带”“全面战场”并列的第三种一级玩法，而不是既有战绩页中的一个筛选项。

它的数据结构与另外两种玩法有本质差异：

- 5v5 队伍对抗；
- 回合制攻守；
- 进攻方围绕 A/B 包点安放黑潮炸弹；
- 防守方阻止安放或完成拆除；
- 回合还可能因全员淘汰、超时、炸弹引爆等原因结束；
- 存在独立经济、装备采购、掉落装备和干员技能体系；
- 评价玩家不能只看 K/D/A，还必须看攻守、回合、目标、首杀、残局、经济和团队贡献。

因此产品上可共用“账号、赛季、模式切换、日期筛选”等外壳，但不应复用烽火或战场的核心指标模型。

## 2. 三份原型的职责

### 2.1 战绩列表：长期战绩中枢

原型包含四层信息：

1. **赛季概览**：总场次、胜率、KDA、总击杀、爆头率、常用枪械、擅长干员、当前与历史段位。
2. **分析维度**：最近对局、地图胜率、枪械 TOP、干员使用、精彩时刻。
3. **单局详情**：比分、双方 5 人战绩版、战斗评分、K/D/A、奖牌、玩家展开详情。
4. **爆破专项**：首杀、回合伤害、下包、拆包、二至五杀、身体命中分布、个人与团队均值比较。

原型里还存在未接通入口的近 7 天汇总、段位趋势、KD 趋势、赛季称号、最佳单局、干员详情和荣誉成就。这些可视为功能池，不应默认全部进入网页端首版。

### 2.2 日报：每日回访与摘要入口

日报不是完整分析页，而是面向回访的“一屏摘要”：

- 日期与当日对局数；
- 当日胜率、MVP、段位变化；
- 击杀、多杀、爆头率、K/D/A；
- 当日最佳对局；
- 进入数据详情或打开游戏的 CTA。

其核心价值是快速回答“昨天打得怎么样”，适合做首页卡片、分享卡或消息召回落地页。

### 2.3 日报数据详情：单日聚合报告

详情页补齐：

- 当日战斗汇总；
- 对局与下包/拆包表现；
- 本命干员；
- 最佳枪械；
- 当日对局列表。

它与长期战绩页不是两个独立数据系统，本质是同一套明细数据在 `day` 时间窗下的聚合视图。

## 3. 推荐的网页端信息架构

### 一级：爆破总览

- 玩家、赛季、段位、最近更新时间；
- 核心指标：场次、胜率、ACS、K/D、KDA、ADR、KAST；
- 爆破专项：进攻胜率、防守胜率、首杀差、下包、拆包、残局胜率；
- 最近趋势；
- 最近对局列表。

### 二级：对局详情

建议使用可分享、可回退的独立 URL，不沿用小程序全屏 Modal：

1. 比赛摘要：地图、队列、时间、比分、时长、段位分变化；
2. 双方战绩版：玩家、干员、评分、K/D/A、ACS、ADR、KAST；
3. 回合时间线：每回合攻守、胜方、结束原因、包点和关键事件；
4. 玩家详情：命中分布、首杀/首死、目标贡献、多杀、残局、经济；
5. 精彩时刻：仅在真实视频或事件数据可用时出现。

### 二级：作战分析

- 地图：场次、整体/进攻/防守胜率、A/B 点成功率；
- 干员：选择率、胜率、KDA、ADR、技能贡献；
- 枪械：使用回合、击杀、爆头率、经济效率；
- 趋势：段位、评分、KD/ADR/KAST；
- 对比：本人 vs 同段位、本人近期 vs 赛季均值。

### 二级：爆破日报

- 默认昨天，支持日期切换；
- 无对局、少量对局、完整日报三种状态；
- 摘要、最佳对局、本命干员、最佳枪械和当日列表共用长期战绩数据；
- 可保留“打开游戏”CTA，但不能把更多数据锁死在游戏跳转之后。

## 4. 推荐数据分层

不要把赛季概览、日报和单局详情分别维护为互不相干的大 JSON。建议保留明细事实层，再生成聚合层。

### 4.1 规则版本 `demolition_ruleset`

- `rulesetVersion`
- `effectiveFrom` / `effectiveTo`
- `teamSize`
- `regulationRounds`
- `roundsToWin`
- `sideSwitchRound`
- `overtimePolicy`
- `roundDurationSeconds`
- `plantDurationSeconds`
- `detonationDurationSeconds`
- `defuseDurationSeconds`
- `economyRules`
- `operatorSelectionRules`

这是必须独立建模的一层。原型使用大量 `13:x` 比分，而目前公开首测资料又出现“率先 6 局获胜”，不能由前端固定推断。

### 4.2 对局 `demolition_match`

- `matchId`：服务端稳定 ID；
- `seasonId`、`rulesetVersion`；
- `queueType`：`casual | ranked | custom | test`；
- `mapId`；
- `startedAt`、`endedAt`、`durationSeconds`；
- `teamAId`、`teamBId`、双方得分；
- `winnerTeamId`；
- `status`：`completed | draw | surrendered | cancelled | invalid`；
- `ranked`、`rankScoreBefore`、`rankScoreAfter`。

### 4.3 对局玩家 `demolition_match_participant`

- `matchId`、`playerId`、`teamId`；
- `operatorId`；若可中途更换，应下沉到回合层；
- `sideAtStart`；
- `kills`、`deaths`、`assists`；
- `combatScore`、`acs`、`damage`、`adr`、`kastRate`；
- `headHits`、`bodyHits`、`legHits`；
- `firstKills`、`firstDeaths`；
- `plants`、`defuses`；
- `clutchAttempts`、`clutchWins`；
- `multiKill2` 至 `multiKill5`；
- `mvpType`、`grade`、`medals`；
- `economyStart`、`economySpent`、`economyEarned`、`economyEnd`。

### 4.4 回合 `demolition_round`

- `matchId`、`roundIndex`；
- `attackerTeamId`、`defenderTeamId`；
- `winnerTeamId`；
- `endReason`：`elimination | detonation | defuse | timeout | surrender | other`；
- `site`：`A | B | none`；
- `plantAt`、`plantPlayerId`；
- `defuseAt`、`defusePlayerId`；
- `durationSeconds`；
- 双方回合初始、消费、结余经济。

### 4.5 回合玩家 `demolition_round_player`

- 存活、击杀、助攻、伤害、承伤；
- 首杀/首死；
- 被补枪/完成补枪；
- 下包、拆包、持包；
- 本回合武器与配件；
- 干员技能购买、使用、命中和贡献；
- 回合结束时装备价值。

KAST、残局、攻守差异、经济转化率等高级指标依赖这一层，不能只由整局 K/D/A 可靠还原。

### 4.6 装备与武器使用

建议区分：

- `loadoutSnapshot`：某回合实际持有的武器、护甲、道具、配件；
- `weaponUsage`：持有回合、开火、命中、击杀、伤害、爆头；
- `economyTransaction`：购买、出售、拾取、回合奖励、击杀奖励、目标奖励。

“常用枪械”应按持有回合或有效使用回合计算，而不是简单按对局去重；一局可能使用多把武器。

### 4.7 精彩时刻 `highlight_moment`

- `momentId`、`matchId`、`roundIndex`、`playerId`；
- `type`：`ace | multi_kill | clutch | plant | defuse | entry | other`；
- `startedAt`、`durationSeconds`；
- `videoUrl`、`thumbnailUrl`；
- `status`：`processing | ready | expired | unavailable`。

无真实视频时不要显示伪播放按钮，可退化为“关键事件时间线”。

### 4.8 聚合结果

按 `player + season/date range + queue + map + side + operator` 聚合，服务：

- 赛季总览；
- 日报；
- 地图、干员、枪械分析；
- 趋势图；
- 同段位基准。

聚合接口必须返回 `sampleSize`、`updatedAt` 和 `metricVersion`，避免低样本百分比误导。

## 5. 指标口径建议

所有指标由统一字典维护名称、公式、分母、空值和版本。

| 指标 | 建议口径 |
| --- | --- |
| 胜率 | 胜利场次 / 已完成且可计入场次 |
| 进攻/防守胜率 | 对应阵营获胜回合 / 对应阵营有效回合 |
| KD | 击杀 / 死亡；死亡为 0 时展示击杀数并标记特殊口径，不伪造无穷值 |
| KDA | 建议 `(K + A) / D`，最终以游戏官方口径为准 |
| ACS | 总战斗评分 / 参与回合数，需确认游戏战斗评分公式 |
| ADR / 回合伤害 | 总伤害 / 参与回合数 |
| KAST | 发生 Kill、Assist、Survive 或 Traded 的回合 / 参与回合 |
| 爆头率 | 必须在“爆头命中 / 总命中”与“爆头击杀 / 总击杀”中二选一并全站统一 |
| 首杀差 | 首杀次数 - 首死次数 |
| 下包成功率 | 成功安放次数 / 有效安放尝试；若无尝试事件，只展示次数 |
| 拆包成功率 | 成功拆除次数 / 有效拆除尝试 |
| 残局胜率 | 残局获胜回合 / 残局尝试回合，并明确 1vN 判定时点 |
| 经济效率 | 每千经济造成伤害或击杀；需基于真实消费而非结算收益 |
| 干员使用率 | 使用回合 / 总参与回合；如规则锁定整局，可改用对局数 |
| 枪械使用率 | 有效持有回合 / 全部可统计回合 |

日报百分比必须由离散场次可还原。例如 3 场比赛不可能得到 82% 胜率，应显示 `2胜1负 · 66.7%`，避免只展示看似精确的百分比。

## 6. 原型中已发现的数据与交互问题

这些问题不能原样复制到网页端：

1. **赛制冲突**：战绩原型大量使用 13 分获胜；公开首测资料存在“率先 6 局获胜”。需以规则版本解决。
2. **3 场 82% 胜率不成立**：日报、干员和枪械均复用了该值。
3. **KDA 8.0 与 34/21/8 不匹配**：无论常见 KDA 公式都无法得到 8.0。
4. **日报列表标题为 5 场，实际只展示 4 条**。
5. **最佳对局日期为 06-28，日报日期为 07-15**，不符合“当日最佳”语义。
6. **高光对局 13:4 共 17 回合，却另写总回合数 6**。
7. **6 回合内出现 4 次下包与 9 次拆包不可能**，说明占位数据未做约束校验。
8. **地图命名不统一**：长期战绩使用航天中转站、蓝水屋电站；日报又出现运河、荒野、临界点、贯穿。
9. **段位体系不统一**：校官/将军与钻石 II 同时出现。
10. **增长值含义缺失**：失败对局也展示正向 `+1,343` 等，可能是经验、收益或活动分，不应误作排位分。
11. **模式切换是假切换**：仅替换对局列表，概览与分析数据仍是爆破数据。
12. **多个功能不可达**：干员详情、趋势、称号、荣誉等有页面无入口。
13. **擅长干员按钮跳错页**：实际仍进入个人能力页。
14. **视频按钮无播放能力**，排行榜流派码只有 Toast。
15. **对局 ID 使用当前时间临时生成**，无法分享、缓存或追踪。
16. **部分单局详情对所有对局复用同一套双方阵容和固定比赛时间**。

## 7. 网页端优先级建议

### P0：可信、可用的战绩闭环

- 模式并列入口；
- 爆破赛季总览；
- 筛选与分页的对局列表；
- 可直达的单局详情；
- 双方战绩版与玩家展开数据；
- 日报摘要与单日详情；
- 完整的空状态、未定级、数据延迟和隐私状态。

### P1：体现爆破差异的分析

- 回合时间线和回合结束原因；
- 进攻/防守拆分；
- 地图与 A/B 点分析；
- 首杀、残局、目标和经济表现；
- 干员、枪械及趋势分析；
- 本人与同段位/团队均值比较。

### P2：依赖内容和全服样本的增强功能

- 精彩视频；
- 全服枪械排行榜与流派码；
- 荣誉称号；
- AI 点评；
- 深度分享卡。

在事件、视频、样本量或指标口径未稳定前，不建议用 Mock 数据把 P2 做成正式功能。

## 8. 后续规划前必须确认的问题

1. 正式模式名是“爆破模式”还是“黑潮爆破”，不同地区是否需要独立名称？
2. 当前和正式版的胜利分数、换边、加时、投降与平局规则是什么？
3. 匹配、排位、自定义是否共用数据，哪些进入段位与日报？
4. 干员是否整局锁定、允许重复、允许回合间更换？
5. 装备和经济是否跨回合继承，购买/出售/拾取/技能升级的完整流水是否可获得？
6. 游戏 API 能提供到对局层、回合层还是事件层？是否包含视频？
7. 官方 KDA、ACS、KAST、爆头率、评分、评级和 MVP 的准确公式是什么？
8. 排位分、经验、收益、活动积分分别叫什么，结算字段如何区分？
9. 地图和段位的正式枚举是什么，测试服 ID 是否会在正式服复用？
10. 日报按自然日还是滚动 24 小时，使用哪个时区，延迟对局如何补算？
11. 隐私玩家、封禁局、异常局、中途退出、重连和无效局如何展示？
12. 全服排行是否有足够样本和反作弊过滤，是否允许按地图、段位、版本筛选？

## 9. 当前产品判断

网页端不应只把小程序界面横向拉宽。正确方向是：

- 将小程序的高密度摘要保留为首页卡片；
- 将单局 Modal 升级为可分享的独立详情页；
- 利用桌面宽度并排呈现双方战绩、趋势和筛选器；
- 用回合、攻守、目标和经济数据建立爆破独有分析能力；
- 用统一明细层同时服务战绩、日报和后续榜单，避免三套口径。

这套基线可以直接进入下一步：结合现有网页端结构，确定爆破入口、页面路由、模块复用关系和 P0 原型范围。

## 10. 爆破改枪页（背包码）规划基线

> 2026-08-14 与需求方对齐后的结论。战绩之外的第二条爆破功能线：改枪方案。

### 10.1 核心概念

- **背包码**：官方配置的整套出装预设。1 套背包 = **16 把枪的改枪方案**。
- **结构**：固定 4 个级别 × 每级 4 把：
  - 手枪
  - 标准
  - 精锐
  - 特种
- 级别的具体定位网页端不需要关心，仅作为展示结构（4 列分组）使用。
- **积分货币**：爆破模式局内经济单位，单枪价格约在 100–10000 区间。网页端展示时每把枪挂积分价格，配一个简洁 SVG icon 示意，**禁止使用 emoji**。

### 10.2 页面位置与形态

- 入口：`desktop/gun-plans.html` 新增第三个模式 tab「爆破模式」，与烽火地带 / 全面战场并列，URL 约定 `?mode=baopo`（与 `my-data.html?mode=baopo` 惯例一致）。
- 布局语言**沿用现有改枪页面**（section、卡片、筛选栏等自有规范），不照搬游戏内背包界面（左侧流派列表 + 右侧详情的布局仅作信息结构参考）。
- 本期只做**桌面端**，mobile 端不做。

### 10.3 功能范围

1. 背包选择：在官方配置的背包列表中切换（数据官方下发，筛选维度待定，首版可不做筛选）。
2. 背包详情：16 把枪按 4 级别分列的宫格；每把枪展示 名称 + 枪图 + 积分价格。
3. **复制背包码**：页面级主 CTA，等价于游戏内的"应用方案"按钮（网页端落地行为 = 复制到剪贴板）。
4. **单枪复制改枪码**：每把枪支持单独复制。
5. 单枪查看详情：**复用现有改枪详情弹窗**（雷达图 + 配件 + 改枪码）；首版可以先不接入点击详情，后续需求方明确要求时再补。

### 10.4 数据模型草案（原型阶段）

```
demolition_backpack
- backpackId
- name                 // 如"道具压制流"
- description?         // 可选，首版可从简
- code                 // 背包码（占位串即可，正式开发再定格式）
- slots[16]
  - tier               // pistol | standard | elite | special
  - weaponId
  - buildName          // 如"K416-三高改枪"
  - points             // 积分价格，100–10000
  - buildCode          // 单枪改枪码（占位串）
```

改枪码 / 背包码的编码格式原型阶段不定义，统一用占位串。

### 10.5 已确认的关键口径

1. **背包数量**：不止个位数，会有很多玩法流派 → 选择器用列表形态（非横向 tab），首版筛选可不做，但结构上要预留筛选位置。
2. **标配手枪无改枪码**：如 G17-标配，仅展示名称 + 枪图 + 积分，不提供复制改枪码；其余手枪（93R、G18、沙漠之鹰等改装方案）有码。
3. **宫格恒为 4×4**：每套背包固定 16 把，不存在空位，不需要弹性空态处理。
4. 背包详情区元信息按"沿用现有改枪页"原则从简，首版仅保留背包名。

### 10.7 管理端范围（2026-08-20 已确认）

- 管理端的唯一管理与发布单元是**背包流派**，即 1 套背包码及固定 `4 × 4 = 16` 把枪配置。
- P0 **不建设爆破单枪方案库**、不提供单枪独立列表/详情/发布/统计；所有枪械配置只存在于所属背包的 16 个固定槽位中。
- 管理端仅有「爆破背包流派管理」：列表、创建/编辑、作者库关联、16 槽位编排、完整性校验、保存草稿/直接发布/下线、版本快照、桌面与移动端只读前台预览。
- 编辑枪位时，在当前背包上下文内填写/修改 枪械名、所属级别、积分、配件与单枪改枪码；这些字段发布后被固化在背包版本快照中，后续修改通过创建背包新草稿版本完成。
- P0 前台的复制/点赞统计以**背包流派**为主体；单枪的独立展示、独立复制、独立点赞/复制统计均不做。
